# Участие в Remo32

Проект начинался как личный пульт для одного дома. Если он пригодился вам —
хорошо; если нашли, что в нём сломано, — тем более.

## Прежде чем открывать issue

Скажите, **что вы делали и что ожидали увидеть**. Одной строки «не работает»
хватает редко. Полезное:

* вывод `./deploy/install.sh check`;
* `journalctl --user -u remo32-controller -n 50` (или `-u remo32-agent`);
* `request_id` из ответа API — по нему одна операция находится в логах
  контроллера и агента сразу;
* версия системы и Python.

**Не вставляйте в issue** содержимое `~/.config/remo32/*.env`, токены,
пароли Wi-Fi и адреса Tailscale. Хэш пароля — тоже секрет.

## Прежде чем присылать изменения

```bash
uv sync
uv run pytest -q
uv run ruff check .
uv run mypy packages
node --check packages/remo32-controller/src/remo32_controller/web/app.js
```

Всё должно быть зелёным. Ровно это же прогоняет CI.

## О чём стоит знать заранее

**Язык.** Комментарии, сообщения об ошибках, интерфейс и документация — на
русском. Идентификаторы, имена файлов и ключи конфигурации — латиницей.
Это не принципиальная позиция, а сложившаяся практика проекта; ломать её
внутри одного файла хуже, чем продолжать.

**Комментарии объясняют «почему», а не «что».** Строка `i += 1` в
пояснении не нуждается. Нуждается решение, которое иначе выглядит
странным: почему опрос, а не прерывание; почему `ignore`, а не `forbid`.

**Опасные операции.** Выключение и перезагрузка в тестах подменяются
`RecordingRunner`. Тест, способный выключить машину разработчика, не будет
принят ни при каких обстоятельствах.

**Границы безопасности.** Их две, и они не обсуждаются:

1. Через API нельзя сконструировать произвольную команду. Действие — это
   типизированное описание, которое превращается в `argv`; строка в
   `shell=True` не уходит никогда.
2. Всё, что даёт исполнение на машине — терминал, правка кнопок — должно
   отключаться одним параметром конфигурации.

Изменение, размывающее любую из них, не пройдёт, даже если очень удобно.

**Секреты не попадают в репозиторий.** Ни в код, ни в тесты, ни в примеры
конфигурации, ни в историю коммитов. Приватные адреса, MAC и SSID — тоже.

## Прошивка

Живёт в `firmware/`, собирается ESP-IDF 5.2+. `ruff` и `mypy` её не
касаются. Учтите: `export.sh` надо **подключать точкой**
(`. ~/esp/esp-idf/export.sh`), а не запускать, и никогда под `sudo`.

## Что скорее всего пригодится

* Windows и macOS: код агента написан по документации и не проверялся.
* Проверка на настоящем железе: оптрон, чтение уровня GPIO, KVM.
* Перевод интерфейса на другие языки — сейчас строки зашиты в разметку.
