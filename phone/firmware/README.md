# Прошивка Remo32 (ESP32-S3)

Аппаратный контроллер: отправляет Wake-on-LAN в домашнюю сеть и сообщает
состояние выводов. Вся остальная логика — в контроллере и агентах, чтобы
подходить к плате с проводом приходилось как можно реже.

**Проверено на живой плате 2026-09-07:** Wi-Fi и токен, HTTP-ручки,
отправка magic packet (доходит до сетевой карты ПК), чтение и изменение
настроек сторожа по сети, перезагрузка по HTTP, запуск обработчика кнопки.
**Не проверено:** нажатие кнопки, пробуждение ПК magic packet-ом и всё
железное из `docs/HARDWARE.md` — оптопара, датчики питания, реле.

---


## Версия ESP-IDF

Собирать нужно **одной и той же** версией. На машине автора их две
(`~/esp/esp-idf` — v5.2, `~/esp/esp-idf-525` — v5.2.5), и подкаталог
`build/` помнит, какой создан:

```
CMake Error: The source ".../esp-idf/components/bootloader/subproject/CMakeLists.txt"
does not match the source ".../esp-idf-525/..." used to generate cache.
```

Лечится `idf.py fullclean` и повторной сборкой. Окружение подключается
**точкой**, а не запускается, и никогда не под `sudo`:

```bash
. ~/esp/esp-idf/export.sh          # именно так, с точкой в начале
cd firmware && idf.py build
idf.py -p /dev/ttyACM0 flash
```

`sudo` здесь только навредит: под root не будет ни виртуального окружения
IDF, ни доступа к `~/.espressif`. Для порта достаточно группы `dialout`.


## Состояние платы владельца

Прошивка залита и проверена на настоящем ESP32-S3 (2026-09-03). Уже сохранено
в NVS: сторож включён, адрес и MAC основного ПК заданы. Осталось ввести:

```
remo32> wifi ИМЯ_СЕТИ ПАРОЛЬ
remo32> token ОБЩИЙ_СЕКРЕТ_С_КОНТРОЛЛЕРОМ
remo32> save
remo32> restart
```

**PSRAM на этой плате неисправен — проверено.** Чип определяется
(`Found 8MB PSRAM device`, `good-die: Pass`), но первое обращение к памяти
вешает систему насмерть, и на 80 МГц, и на 40 МГц. `CONFIG_SPIRAM` должен
оставаться выключенным. Для задач с кадровым буфером (тачскрин с LVGL) эта
плата непригодна — нужна другая.

ESP-IDF 5.2 или новее. На машине владельца уже установлен:

```bash

```

## Сборка

```bash
cd firmware
. ~/esp/esp-idf-525/export.sh
idf.py set-target esp32s3
idf.py build
```

Ожидаемый результат:

```
remo32_firmware.bin binary size 0xda740 bytes.
Smallest app partition is 0x300000 bytes. 0x2258c0 bytes (72%) free.
```

## Заливка

Плата определяется как `/dev/ttyACM0` (мост CH343). Убедитесь, что вы в
группе `dialout`:

```bash
groups | grep dialout || sudo usermod -aG dialout $USER   # затем перелогиниться
```

```bash
idf.py -p /dev/ttyACM0 flash monitor
```

Если плата не переходит в режим загрузки автоматически: удерживайте
**BOOT**, коротко нажмите **RESET**, отпустите **BOOT**.

Выход из монитора — `Ctrl+]`.

## Первичная настройка

Секретов в прошивке нет. После заливки плата ждёт настройки через
последовательный порт. Подключитесь монитором и введите:

```
remo32> wifi ИМЯ_СЕТИ ПАРОЛЬ
remo32> token ОБЩИЙ_СЕКРЕТ_С_КОНТРОЛЛЕРОМ
remo32> id esp32-main
remo32> save
remo32> restart
```

### Сторож основного ПК

Главная задача платы в текущей схеме. Контроллер работает на основном ПК и
себя разбудить не может — если тот умрёт, командовать некому. Плата делает
это сама:

```
remo32> guard --on --host 192.168.1.10 --mac 5c:f9:dd:11:22:33 --bcast 192.168.1.255
remo32> guard --grace 10 --retry 15 --tries 3
remo32> save
remo32> restart
```

Проверить состояние в любой момент — `guard` без аргументов:

```
сторож:      включён
состояние:   наблюдение
ПК:          192.168.1.10 (5c:f9:dd:11:22:33)
ожидание:    10 мин, пауза 15 мин, попыток 3
побудок:     0 (в серии 0)
```

Состояния: `наблюдение` (ПК на связи), `ПК пропал` (идёт отсчёт),
`побудка` (пакет отправлен, ждём загрузки), `попытки исчерпаны` (ПК,
видимо, обесточен), `плановое выключение` (контроллер попросил помолчать).

Адрес ПК стоит закрепить в роутере: сменится IP — сторож будет считать
живой компьютер пропавшим и попытается его «разбудить».

Для удалённой работы (плата дома, контроллер в другом месте) добавьте
брокер:

```
remo32> mqtt mqtts://брокер:8883 ПОЛЬЗОВАТЕЛЬ ПАРОЛЬ
remo32> save
remo32> restart
```

Все команды консоли:

| Команда | Назначение |
|---|---|
| `wifi <ssid> [пароль]` | Сеть Wi-Fi |
| `mqtt <uri> [польз.] [пароль]` | Брокер MQTT (необязательно) |
| `token <значение>` | Общий секрет с контроллером |
| `id <значение>` | Идентификатор устройства |
| `guard [--on\|--off] [--host] [--mac] [--bcast] [--grace] [--retry] [--tries]` | Сторож основного ПК |
| `guard --snooze <мин>` | Не вмешиваться указанное время |
| `show` | Показать настройки (пароли скрыты) |
| `save` | Записать в NVS |
| `erase` | Стереть настройки |
| `restart` | Перезагрузить |
| `help` | Список команд |

Настройки живут в отдельном разделе NVS и переживают перепрошивку
приложения. Полностью стереть: `idf.py -p /dev/ttyACM0 erase-flash`.

## Проверка после настройки

В домашней сети (транспорт `http`):

```bash
curl http://АДРЕС_ПЛАТЫ/ping
curl -H "X-Remo32-Agent-Token: ВАШ_ТОКЕН" http://АДРЕС_ПЛАТЫ/status
```

Ответ `/status` должен содержать `"simulated": false` — так вы отличите
настоящую плату от симулятора.

Затем в конфигурации контроллера:

```toml
[esp32]
transport = "http"
base_url = "http://АДРЕС_ПЛАТЫ"
```

и перезапустить контроллер.

## Структура

```
firmware/
├── CMakeLists.txt
├── sdkconfig.defaults      цель, PSRAM выключен, сторожевой таймер
├── partitions.csv          два раздела приложения — задел под OTA
├── main/main.c             порядок запуска
└── components/
    ├── r32_config/         настройки в NVS + консоль
    ├── r32_wifi/           подключение и восстановление связи
    ├── r32_gpio/           таблица выводов, чтение и запись
    ├── r32_wol/            magic packet
    ├── r32_proto/          разбор команд, сборка ответов (cJSON)
    ├── r32_http/           локальный HTTP-сервер
    └── r32_mqtt/           MQTT-клиент с последней волей
```

Протокол не зависит от транспорта: `r32_proto` обрабатывает одну и ту же
команду независимо от того, пришла она по HTTP или из MQTT.

## Решения, заслуживающие пояснения

**Сторожевой таймер на 30 секунд.** Задача `heartbeat_task` подписана на
него и сбрасывает каждые 10 секунд. Если сетевой стек заблокируется, плата
перезагрузится сама — подойти к ней и нажать кнопку может быть некому.

**Пауза переподключения растёт до минуты.** Если роутер выключен надолго,
бессмысленно молотить эфир каждую секунду. После успешного подключения
пауза сбрасывается обратно до секунды.

**Последняя воля MQTT.** Плата публикует `offline` в топик
`availability` как LWT. Если она пропадёт, брокер объявит это сам, и
контроллер узнает сразу, а не по таймауту.

**Статус публикуется с retain.** Контроллер, подключившись позже, сразу
видит состояние платы, не дожидаясь следующего периодического сообщения.

**`kvm` не объявляется в `capabilities`.** Физического переключателя нет,
и прошивка не делает вид, что он есть: контроллер честно вернёт 501.

**Сравнение токена постоянно по времени.** Иначе по времени ответа можно
было бы подбирать токен посимвольно.
