# JustDay — правила работы

Этот файл читают обе оболочки: Claude Code (через `CLAUDE.md`, он ссылкой сюда) и OpenCode
(`AGENTS.md` он берёт сам). Правила одни и те же, в какой бы из них ни шла работа, — иначе смена
модели посреди дела означала бы ещё и смену привычек.

## Что это

Личный ассистент для Linux (KDE Plasma 6, Wayland): демон на Python и оболочка на QML/Quickshell —
Dynamic Island, док, лоток, меню, Spotlight. Голос, окна, музыка, почта, видео. Мозг — Claude Code
через Agent SDK; при лимите спускается по лестнице поставщиков.

- `src/justday/` — демон, инструменты, CLI (`justday …`).
- `island/` — всё, что видно на экране.
- `shell/opencode/` — лестница нейросетей для оболочки OpenCode.
- `src/justday/terminal.py`, `terminal_ui.py` — своя оболочка: один терминал, лестница движков
  (`docs/ОБОЛОЧКА.md`).
- `docs/ПЛАН.md` — что делаем и в каком порядке. Это очередь, а не список пожеланий.

## Где ты сейчас работаешь

Прочитай это первым: от того, как ты запущен, зависит, что у тебя получится, а что отклонится.
Проверить можно так: `echo $JUSTDAY_SHELL` — пусто (человек рядом), `terminal` (наша оболочка),
`opencode` (чужая); `echo $JUSTDAY_NIGHT` — `1` значит, что человек спит и подтверждать некому.

**Четыре места, где ты можешь оказаться.**

1. **Сам Claude Code, человек рядом.** Обычный разговор. Подтверждения приходят к человеку, он
   отвечает голосом или мышью. Самый свободный случай.
2. **Движок внутри нашей оболочки** (`justday terminal`, `JUSTDAY_SHELL=terminal`). Тебя запустили
   как `claude -p` одной задачей: ты её делаешь и заканчиваешь ход. Над тобой — лестница; если у
   тебя кончится лимит, ту же задачу продолжит другая нейросеть, и она не увидит ничего из того,
   что видел ты. Отсюда главное правило: **всё важное пиши на диск по ходу дела**
   (`ПЕРЕДАЧА.md`), а не в конце ответа.
3. **Мозг голосового Джарвиса** (демон, `brain.py` через Agent SDK). Тебя спрашивают голосом,
   ответ читают вслух, и его слышно целиком — пиши коротко, без разметки и без списков.
4. **OpenCode** (другая оболочка, `AGENTS.md` она читает сама). Инструменты называются иначе,
   правила те же.

**Что отклоняется само, без человека.** В оболочке ночью (`justday terminal --night`, в окне
`/night`) ты запущен с `--permission-prompts none`: всё, что потребовало бы подтверждения,
отклоняется сразу. Это не ошибка настройки и не повод искать обход — человек спит, спросить
некого, и «некого» значит «нельзя». Что делать вместо попыток: сделать всё, что можно без
подтверждения, а в конце написать **одной строкой**, что именно нужно от человека. Он прочитает
утром в журнале (`~/.local/state/justday/ночь/<дата>.md`) и решит сам.

Чего не делать никогда, даже когда очень мешает: `--dangerously-skip-permissions`,
`permission_mode=bypassPermissions`, правка `brain/settings.json` ради тишины. Снятая защита — не
забота об удобстве человека, а снятая с него защита. На это есть тест
(`tests/test_terminal.py`), и он упадёт.

**Лимиты и деньги.** На верхней ступени работает подписка человека, и лимит у неё один на всё:
потраченный на мелочь к вечеру не вернётся. Поэтому не зови сильную модель и высокое усилие туда,
где хватит простого ответа; оболочка выбирает это сама (`dispatch`), но и ты не раздувай работу
без нужды. Подписку Claude нельзя отдавать сторонним программам — Anthropic разрешает вход по
подписке только своим Claude Code и claude.ai, и обходить это мы не будем (`docs/ПЛАН.md`, пункт
про Anthropic).

**Тебя могут сменить посреди дела.** Лимит кончается без предупреждения. Пришедшему на смену
достанется задача человека, твой последний ответ и `ПЕРЕДАЧА.md` — больше ничего. Веди этот файл
так, будто тебя выключат на следующей минуте, потому что так и будет.

## Общие правила

Поверх этого файла действуют `docs/ПРАВИЛА.md` — они общие для всех сессий и всех оболочек:
работать до конца, вести `ПЕРЕДАЧА.md`, пользоваться инструментами, и список того, что проверяется
перед выпуском наружу. Если что-то противоречит — верх берут общие правила.

## Язык

Всё по-русски: ответы человеку, комментарии в коде, сообщения коммитов, тексты на экране.
Английский остаётся там, где он и был: имена переменных, API, названия инструментов.

## Комментарии

Комментарий объясняет **почему**, а не что. «Увеличиваем счётчик» писать не надо — это видно.
Надо писать то, чего в коде не видно: какая беда была, какой случай сломался, почему выбран этот
путь, а не очевидный. Хороший комментарий переживает переписывание функции.

## Проверки перед коммитом

```sh
ruff check .
.venv/bin/python -m pytest -q
/usr/lib64/qt6/bin/qmllint -I . island/ИМЯ.qml      # для изменённых QML
bash -n install.sh                                  # если трогали установщик
```

Тесты пишутся на то, что **сломалось у человека**, а не на то, что легко проверить. В названии и
в docstring — беда, а не механика: «одна настройка ломала весь конфиг», а не «проверка set_value».

## Выкладка

```sh
git push origin main
git -C ~/.local/share/justday/app pull -q --ff-only
systemctl --user restart justday justday-ui
```

Ветка `main` защищена правилом: чужой push требует одобрения, владелец проходит.

## Чего делать нельзя

- Ключи, пароли и токены — только в связке ключей рабочего стола (`secret-tool`). Не в конфиге,
  не в исходниках, не в памяти ассистента. В оболочку они попадают переменными окружения.
- Управляющий сокет и любой наш порт наружу не смотрят: только 127.0.0.1.
- Необратимое (удаление, оплата, отправка) спрашивает подтверждение. Запуск программы — не
  спрашивает: подтверждение на каждый пуск это не безопасность, а шум.
- Сервер minevpsex и плату ESP32 не трогать.
- Отключать защиту ради простоты установки нельзя.

## Как выглядит сделанная работа

Коммит объясняет причину, а не перечисляет файлы. Сообщение пишется так, чтобы через полгода было
понятно, какую беду оно чинило. Хвост у коммитов — соавторство и ссылка на сессию.
